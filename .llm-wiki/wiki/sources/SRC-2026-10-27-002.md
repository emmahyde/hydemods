# fix-cofounder-feedback.md

## Summary

This command defines an end-to-end, resumable workflow for investigating one piece of Cofounder user feedback from Slack or a Braintrust trace. It requires evidence-based diagnosis, a user-approved fix plan, a reproducing eval, implementation in an isolated worktree, and a draft PR.

The workflow treats the invoking user as the only source of direction and uses explicit state to survive repeated invocations. It also defines safeguards for production data, outbound Slack and GitHub content, read-only replica access, worktree pooling, eval acceptance thresholds, and command improvements.

## Key Takeaways

- Do not implement until the invoking user approves the posted root cause, proposed fix, and eval plan.
- Prove the eval fails at least 7/10 runs before the fix and passes at least 9/10 afterward; investigate provider errors and misleading mock behavior rather than counting them as valid results.
- Keep customer identifiers and customer-authored text out of Slack, commits, PRs, and source files; require the outbound checker before posting or pushing.
- Preserve production dumps only in the local per-feedback cache, remove them at closeout, and publish only draft PRs.
